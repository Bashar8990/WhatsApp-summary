# ملخص الواتساب

تطبيق ويب تقدمي (PWA) عربي بالكامل يحلّل محادثات واتساب **محليًا داخل جهاز المستخدم** دون إرسال أي نص إلى أي خادم خارجي. يستخرج التطبيق: الملخص، المهام المطلوبة من المستخدم، المهام العامة، المواعيد، القرارات، والأشخاص وأدوارهم.

## المميزات

- **خصوصية كاملة**: المحادثة لا تغادر جهازك أبدًا. لا يوجد خادم خلفي، لا حسابات، لا تحليلات، لا مفاتيح API.
- **تحليل ذكي محلي** عبر [WebLLM](https://github.com/mlc-ai/web-llm) و WebGPU (اختياري).
- **تحليل سريع برمجي** يعتمد على القواعد كخيار احتياطي لا يحتاج أي نموذج.
- **PWA** قابل للتثبيت ويعمل دون اتصال بعد تحميل الملفات والنموذج.
- **RTL** عربي بالكامل، تصميم متجاوب Mobile First، وضع فاتح وداكن.
- **تخزين محلي** للنتائج عبر IndexedDB (مع موافقة المستخدم).
- **تقسيم المحادثات الطويلة** إلى أجزاء ودمج النتائج.
- **نسخ وتصدير** النتائج بصيغة TXT و JSON.

## طريقة التثبيت والتشغيل

المتطلبات: Node.js 20+ و npm.

```bash
npm install
npm run dev
```

ثم افتح الرابط الظاهر في المتصفح (عادة http://localhost:5173).

## طريقة البناء

```bash
npm run build
npm run preview   # معاينة نسخة الإنتاج محليًا
```

الناتج في مجلد `dist/`.

## كيف يعمل WebLLM

يستخدم التطبيق مكتبة [WebLLM](https://github.com/mlc-ai/web-llm) لتشغيل نماذج لغة محليًا داخل المتصفح باستخدام **WebGPU** عند توفره. النموذج يُحمّل مرة واحدة عبر الإنترنت ثم يُخزّن داخل المتصفح (Cache API) ليعمل دون اتصال بعدها. **نص المحادثة لا يُرسل إلى الإنترنت إطلاقًا** — كل المعالجة تتم على الجهاز.

عند عدم توفر WebGPU أو فشل تحميل النموذج، يتحول التطبيق تلقائيًا إلى **التحليل السريع البرمجي** الذي يعتمد على قواعد مطابقة الكلمات المفتاحية.

## كيفية تغيير النموذج

اسم النموذج وإعداداته موجودة في ملف واحد فقط:

```ts
// src/config/model.ts
export const MODEL_CONFIG = {
  modelId: 'Hermes-2-Theta-Llama-3-8B-q4f16_1-MLC',
  displayName: 'Hermes 2 Theta Llama-3 8B (q4f16)',
  estimatedSizeMB: 4500,
  contextWindow: 4096,
  temperature: 0.1,
  maxTokens: 1500,
};
```

يمكنك تصفح النماذج المتاحة من [WebLLM models](https://github.com/mlc-ai/web-llm/blob/main/src/config.ts) وتغيير `modelId`. يُفضّل اختيار نموذج خفيف مناسب للجوال.

## حدود الأجهزة والمتصفحات

- **WebGPU** مطلوب للتحليل الذكي المحلي. مدعوم في Chrome/Edge حديث على الحواسيب، وبعض الأجهزة المحمولة.
- إذا لم يتوفر WebGPU، يستخدم التطبيق التحليل السريع البرمجي تلقائيًا.
- تحميل النموذج يحتاج ذاكرة كافية (يُفضّل 4GB+ RAM) ومساحة تخزين.
- التحليل الذكي قد يكون بطيئًا على الأجهزة الضعيفة.

## شرح الخصوصية

- التطبيق يحلل المحادثة داخل جهاز المستخدم بالكامل.
- لا توجد حسابات مستخدمين ولا خادم خلفي.
- لا يتم إرسال نص المحادثة إلى أي مزود خارجي.
- قد يحتاج تنزيل النموذج إلى اتصال بالإنترنت (مرة واحدة)، لكن المحادثة نفسها لا تُرسل.
- النتائج المحفوظة تبقى داخل متصفحك (IndexedDB).
- حذف بيانات المتصفح قد يحذف السجل والنموذج.
- المستخدم مسؤول عن الحصول على الإذن المناسب قبل تحليل محادثات الآخرين.
- لا توجد خدمات تحليلات أو تتبع. لا يُسجّل نص المحادثات في console في وضع الإنتاج.

## شرح وضع التحليل السريع

التحليل السريع (Rules-only) هو طبقة برمجية تعتمد على مطابقة الكلمات المفتاحية العربية (مع إزالة التشكيل) لاستخراج:

- **الأشخاص**: من أسماء المرسلين وعدد رسائلهم.
- **المواعيد**: من كلمات مثل (غدًا، اليوم، الساعة، اجتماع، موعد...).
- **المهام**: من أفعال التكليف مثل (أرسل، جهّز، حضر، راجع، لا تنس...).
- **القرارات**: من كلمات مثل (تم الاتفاق، تقرر، اتفقنا، نعتمد...).

النتائج تقريبية وقد تحتوي على إيجابيات/سلبيات كاذبة، لكنها تعمل على أي جهاز دون نموذج. الواجهة توضح دائمًا أن هذه النتائج تقريبية.

## النشر المجاني

### GitHub Pages

```bash
npm run build
# انشر محتويات مجلد dist/ عبر GitHub Pages
```

أو استخدم إجراء GitHub Actions لرفع `dist/`. مع PWA، تأكد من ضبط `base` في vite.config.ts إذا كنت تنشر تحت مسار فرعي.

### Cloudflare Pages

1. اربط المستودع بـ Cloudflare Pages.
2. أمر البناء: `npm run build`.
3. مجلد الإخراج: `dist`.

### Netlify

1. اربط المستودع بـ Netlify.
2. أمر البناء: `npm run build`.
3. مجلد النشر: `dist`.

## ملاحظات تقنية

- مكتبة WebLLM كبيرة (~6MB) وتُحمّل ديناميكيًا فقط عند طلب التحليل الذكي أو تحميل النموذج، ولا تُحمّل عند فتح الصفحة.
- Web Worker متاح للتحليل البرمجي الثقيل لمنع تجمّد الواجهة.
- التطبيق يتحقق من JSON الناتج عن النموذج (إزالة markdown، إصلاح الأخطاء، التحقق بـ Zod، قيم افتراضية) ويعيد المحاولة بصيغة أكثر صرامة، ثم يلجأ للتحليل البرمجي عند الفشل.
